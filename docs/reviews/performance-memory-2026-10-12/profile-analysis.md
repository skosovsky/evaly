# Selected JSON optimization profiles

Separate baseline/candidate runs use Go 1.27.1, GOMAXPROCS=8, identical 16KiB capture and SavedView benchmarks, `-benchtime=1s`, CPU and default sampled allocation profiles. They are excluded from gate samples. Raw `*.cpu.pprof` / `*.alloc.pprof` and `*-top.txt` are retained. Frames are symbolized in the profiles; `go tool pprof -top -alloc_space <profile>` reproduces the allocation view without a separate test binary.

Baseline allocation hotspots: JSON decoder fetch (51.53% flat), bytes.Clone (23.51%), JSON token strings (10.43%), RawMessage UnmarshalJSON (7.77%). SavedView record cloneJSON accounts for 10.79% cumulative; Event cloneJSON and EvidenceRecord cloneJSON also appear. This supports removing JSON round-trip work on library-owned wire records while retaining external validation and domain codecs.

Candidate allocation profile exposes direct cloneSavedViewRecord/slices.Clone and cloneEvidenceRecord paths. SavedView cloneJSON remains at the public Save/Restore boundaries (3.48% cumulative); the old Event cloneJSON/Seal mustCloneJSON paths no longer appear among hot frames on these valid UTF-8 fixtures. CanonicalJSON/readJSON remain substantial because external validation, projection validation, built-in encoding and Restore/Rescore preflight are intentionally retained. FieldPolicy.Project remains a hotspot; this task does not weaken its untrusted payload validation.

CPU profiles still show JSON string scanning/quoting and runtime allocation/scheduling/GC work. The share of ConsumeSimpleString is 17.56% baseline and 14.81% candidate in these aggregate runs. Absolute total profile bytes/time cannot be compared as per-invocation savings: benchmark adaptation runs more candidate iterations and aggregate benchmark mixes are not fixed invocation counts. Use final benchmark medians in gates.json for performance conclusions. Profile output represents allocation volume (`alloc_space`), not retained heap, RSS, or a leak.
