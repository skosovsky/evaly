# Bounded search contract (search v4)

The host supplies typed candidate codecs, revisioned proposer, objective and constraints. Every search uses one proposal protocol, including static enumeration. Proposals see sealed training/calibration datasets and cloned service feedback only. Feedback includes lineage, objective aggregate measurements, missingness/failure reasons; raw trials, outputs and references are absent unless an explicit revisioned host projection returns permitted references. Holdout data is never a proposal input. Holdout baseline structural validation does not call the objective before selection.

Rounds are zero based, bounded by MaximumRounds, MaximumCandidates and Timeout. Proposal and evaluation dispatches have deterministic unique search/round/phase identities and budget Reserve/Claim authorization. Claimed identities cannot dispatch twice. EvaluationUnits bounds orchestration dispatch liability separately from target/grader reservations inside Evaluate. Unknown usage retains liability; paid proposal usage and available experiment records survive errors. Cancellation, budget, deadline and structural protocol failures stop all subsequent dispatches. An empty proposal or explicit Exhausted flag means normal exhaustion; reaching configured round/candidate limits stops further search and forbids holdout.

Ranking uses the declared objective direction, with lexical candidate revision ties (candidate-revision-lexical-v1). BestMeasured records the best comparable native measurement, including infeasible candidates. Winner requires a sealed complete experiment, sufficient comparison, and revisioned host feasibility. Gate failure remains a measured candidate; winner additionally requires GatePass. No eligible winner is explicit. Selection is fixed before holdout, whose failure never starts another round. Holdout reuse is recorded through the host ledger. ID disjointness is mandatory; independence is claimed only after successful revisioned host split validation.

Search v4 records ordered rounds and evaluations, policy identities, stop state, constraints, comparison measurements and optional host projected references. Candidate records remain codec-owned generic descriptions with canonical content revisions. Restore verifies revisions and typed candidate descriptions, supported wire versions and structural invariants; it never invokes target or proposer. Old one-shot Config.Candidates and Validate are removed.

`Constraints[T]` receives a fresh decoded candidate and copied service measurement summary, including gate verdict. Candidate validity is codec-owned; constraint feasibility cannot override an incomplete experiment or failing gate. Ties compare full candidate revisions. Experiment IDs hash the full search ID, phase and candidate revision, fitting the artifact limit without truncating identity inputs; the separate claim identity includes round and position. All proposal attempts, including invalid encodings and duplicate identities, consume candidate capacity. Static proposers receive sealed candidates and decode a fresh value for each request.

`EvaluationUnits` reserves dispatch overhead independently of Evaluate's target/grader budget. A zero-unit claim still authorizes exactly one dispatch; a positive bound remains unknown liability because Evaluate returns an experiment rather than a separate overhead usage receipt. Proposal usage is reconciled even on callback failure; invalid nonfinite usage becomes unknown liability and stops search. Round `Received` preserves safe identity metadata of proposals returned together with errors, without dispatching or encoding those failed proposals. Unsealed invalid proposal history carries identity metadata but no revision or description; restore permits that shape only for invalid entries.

`ValidateResult` checks service structure, revisions, comparison identity, deterministic ranking and selection. `RestoreResult[T]` additionally restores every sealed candidate with the caller codec and returns an independent copy. Neither operation invokes objective, constraints, proposer or evaluation callbacks.
